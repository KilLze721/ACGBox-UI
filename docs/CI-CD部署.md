# 前端自动部署

本仓库的 `.github/workflows/cicd.yml` 在推送 `main` 时执行现有 Vitest 测试、类型检查和生产构建，成功后通过 SSH 自动部署。PR 只检查，不连接生产服务器；也支持在 Actions 页面手动运行 `main`。

服务器的一次性安装、SSH 密钥和两个仓库都需要的 Secrets，见后端仓库 `deploy/README.md`。现有网站根目录 `/www/wwwroot/acgbox` 保持不变。部署先复制资源，再原子替换 `index.html`，保留旧哈希资源和旧版本快照，检查页面失败时恢复旧文件。

上传使用 rsync 的 `--copy-dest=/www/wwwroot/acgbox`，在新提交的暂存目录复用网站已有的相同文件；变化文件使用增量传输。`--checksum` 按内容比较，`--partial-dir=.rsync-partial` 保留中断文件供同一提交重跑时复用。上传阶段不会修改正在提供访问的网站文件，只有上传成功才调用现有服务器部署脚本。SSH 继续严格校验服务器公钥；阶段日志区分 GitHub 提交检查、SSH 连接、资源上传和服务器发布。

## 首次启用

服务器已通过后端流程完成初始化，前端沿用 `acgbox-deploy` 账号和同一个部署脚本，无需再次安装服务器工具。

1. 在 `KilLze721/ACGBox-UI` 仓库的 Actions Secrets 中分别配置 `DEPLOY_HOST`、`DEPLOY_PORT`、`DEPLOY_USER`、`DEPLOY_SSH_KEY`、`DEPLOY_KNOWN_HOSTS`。这些值可以与已跑通的后端仓库相同，仓库之间不会自动共享 Secrets。
2. 核对准备提交的测试修订。当前通过验证的工作区包含现有 `src/__tests__` 修订和两项既有测试文件删除；仅提交工作流不会将这些修订上传，GitHub 仍会运行仓库原来的测试。
3. 提交所需的测试修订、工作流和本说明，再推送 `main`。本次没有自动提交或推送任何文件。
4. 在 GitHub Actions 中查看 `Frontend CI/CD`，应依次通过现有测试、构建、资源上传、服务器发布。
5. 发布后访问 `http://192.144.149.163:8081`，核对登录页、页面刷新、已有列表和本次变更。更新静态文件不需要重启后端容器。
